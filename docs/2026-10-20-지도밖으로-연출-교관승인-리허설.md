# 2026-10-20 스토리·세계지도·교관 해독 승인·리허설 개편

> **최신 웹 게임의 기준 문서.** 기존 44분대 구조/제7초소/3개 엔딩과, 임의 답안에 대한 자동 정답판정은 옛 기획이다. 이 문서를 기준으로 준비하고 테스트한다.

## 1. 최종 스토리: 「마지막 계승자 — 지도 밖으로」
- **1막·출정:** 사람들을 지킨 방벽. 벽 밖은 거인이 점령한 죽음의 땅이라는 소문 때문에 지도 밖은 검게 가려져 있다. 네 분대에 여섯 거인 토벌·계승 명령.
- **2막·의심:** 거인마다 내부 공방·군수품·제어 신호·실험 기록의 흔적이 발견된다. 동시에 밖에서 얻은 신선한 과일과 오래된 바깥 탐사 지도까지 나온다.
- **3막·위기:** 3라운드 직후 초대형 거인 방어전. 방어 성공 또는 비상 방어 종료 뒤 **인류 방어 계획 — 제어 시스템 폭주** 기록을 발견한다.
- **4막·두 반전:** 거인은 벽 밖에서 침공해 온 생명체가 아니라 **방벽 내부의 인류 보호용 방어 병기**였고 **제어 시스템 폭주**로 인류의 적이 됐다. 이후 벽 밖 탐사가 중단되고 미확인 지역을 검게 칠하면서 사람들은 죽음의 땅이라는 소문을 믿게 되었다. 실제 옛 기록에는 **강·숲·과수원·길**이 있었다.
- **5막·새 지도:** 모든 분대가 각자 해독을 교관 승인받으면, 검은 지도가 걷히는 애니메이션과 진실 공개. 거인과 과거를 불쌍하게 만들지 않고 **적을 무찌르는 성장·미지의 세계로 향하는 열정**에 초점을 둔다.
- **두 엔딩:** **계승**은 위험을 관리하며 거인의 힘으로 개척, **해방**은 제어 장치를 봉인하고 사람들의 협동으로 개척. 둘 다 방벽을 딛고 밖으로 출정하며 우열은 없다.
- **공통 마지막 문장:** '옛 지도는 여기서 끝난다. 그러나 우리의 이야기는 이제부터다!'

## 2. 라운드와 실제 부스 (변경하지 않음)
- 4팀 A~D · 각 6명, 6개 순환 부스, 각 7분(활동·이동 포함), 3R 뒤 8분 공동 방어.
- ① 차력: 젓가락으로 콩 옮기기; ② 짐승: 신발을 던져 소쿠리로 받기; ③ 여성형: 소금물 마신 뒤 표정 연기; ④ 턱: 밀가루 속 사탕 찾기; ⑤ 갑옷: 얼굴 포스트잇 입김으로 떼기; ⑥ 전퇴: 팀원마다 서로 다른 종이접기.
- 차력/짐승은 교관이 0~10점 수동 승인, 나머지는 분대장 완료 보고 시 10점. 채점 세부 기준은 현장 운영진 최종 결정이 필요함.
- 공동 방어 A 줄넘기 5회 연속, B 퀴즈 1개, C 젠가 수직 5개 쌓기, D 티스푼 탁구공 릴레이.
- 4팀의 24개 부스 완료 후 관리자가 '최종 작전 개방'. 4팀 각각 퍼즐 승인과 엔딩 선택을 마쳐야 공통 에필로그 가능.

## 3. 여섯 조사 기록과 지도 효과
| 거인 | 최신 기록 | 화면 지도 |
|---|---|---|
| 차력 | 군수창고 봉인과 외부 과일 | 회수 시 1조각 반투명 |
| 짐승 | 제3공방 무기 제조 번호 | 회수 시 1조각 반투명 |
| 여성형 | 방벽 내부 제어시설의 신호 | 회수 시 1조각 반투명 |
| 턱 | 인류 방어 계획 문서 | 회수 시 1조각 반투명 |
| 갑옷 | 제어 시스템 폭주·통제 불능 | 회수 시 1조각 반투명 |
| 전퇴 | 검게 칠해진 지도와 다른 탐사 기록 | 회수 시 1조각 반투명 |

각 분대의 미확인 조각은 어두운 안개로 덮인다. **퍼즐 승인 후** 세계지도 전체에 색이 돌아오고 안개 6개가 시간차로 사라지는 애니메이션이 나타난다. 효과음 없음. 화면 흔들림 감소 설정(prefers-reduced-motion)을 존중한다.
주의: 조각 배열은 시각적 수집 표시이지 실제 지리 좌표를 주장하는 게 아니다. 별도 이미지 API/영상이 없어도 웹 표준 SVG와 CSS로 표시된다.

## 4. 퍼즐 — 자유 입력 · 무조건 교관 검토
| 번호 | 질문 | 운영진 참고 정답 |
|---|---|---|
| 1 | 거인은 어디에서 만들어졌는가? | 방벽 내부 |
| 2 | 거인은 무엇을 위해 만들어졌는가? | 인류 보호 |
| 3 | 거인들이 인류의 적으로 변한 원인은? | 제어 시스템 폭주 |

**자동 정답 판정은 하지 않는다.** 분대장은 세 답안을 자유 텍스트로 제출한다. 서버는 길이(항목당 1~120자)와 권한만 검증하고 `puzzleSubmission.status='pending'`으로 저장한다. 승인 대기 중 중복 제출 불가.
관리자 **본부 제어 → 최종 퍼즐 · 교관 승인 대기**에서 각 분대의 답안을 확인하고 **해독 승인** 또는 **재도전 안내**를 선택한다.
- **승인:** 해당 분대의 `puzzle=true`, 두 반전·복원된 지도·엔딩 선택 공개
- **재도전:** 제출 기록을 보존한 채 `rejected`로 표시, 분대장이 다시 제출 가능
- *관리자만 승인·반려 가능*. 분대원은 조회만 가능하며, 다른 팀의 해독 내용은 보이지 않는다.
- 특정 글자에 지나치게 매이지 말고 두 번의 반전과 폭주 원인을 정확히 설명했는지를 보고 운영진이 판단한다.

## 5. 관리자 1대 기기 리허설 (운영 DB 비변경)
1. 관리자로 로그인 → **본부 제어 → 1대 기기 리허설 → 리허설 시작**.
2. 화면 상단의 **장면 선택** 드롭다운에서 12장면을 원하는 순서로 탐색한다.
3. 역할을 **관리자 / 분대장 / 분대원**으로 바꾸고 A~D분대도 선택해서 실제 앱의 화면 요소를 확인한다.
4. 검토 과정 시험: 8번째 장면(퍼즐 승인 대기) → 관리자 화면 → 본부 제어의 **해독 승인** → 9번째 장면(승인 완료). 분대장 화면에서 지도 복원과 엔딩 선택 확인.
5. **계승 / 해방 / 에필로그** 장면을 차례로 확인한다. 역할·장면 전환 및 퍼즐 폼의 제출 동작은 **미리 준비한 가상 상태로 전환될 뿐 저장되지 않는다**.
6. **리허설 종료**로 실서버 조회 화면에 복귀한다.

**리허설 안전성:** `POST /api/game`의 `rehearsal` 동작은 인증된 관리자로 제한한다. API는 `lib/rehearsal.mjs`가 생성한 가상의 프로젝트 상태만 반환하며, `gateway('write')` 및 `updateState`를 호출하지 않는다. 게임 진행 상태·실제 분대장 권한·점수·결말은 변경되지 않는다. 다만 일반 API와 동일하게 요청 횟수 제한 카운터는 갱신된다. 실제 부스의 물리적 성공, 서버 DB 동시 제출, 운영 배포까지 대신 시험하지는 않는다.
