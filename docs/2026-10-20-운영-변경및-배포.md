## GitHub → Vercel 배포
1. GitHub의 이 기능 브랜치에서 변경 파일과 테스트 결과 확인 후 main에 PR 병합.
2. **GitHub 연결에 의한 자동 배포가 설정되지 않았다.** 병합만으로 https://last-inheritor.vercel.app 사이트는 변경되지 않는다.
3. 현재 Vercel 프로젝트 last-inheritor의 배포 방식(기존 소스 업로드)을 이용해 main의 최신 소스를 재배포한다. 배포 대상: `public/`, `api/`, `lib/`, `package.json`, `package-lock.json`, `vercel.json`.
4. 서버 환경변수와 데이터베이스는 유지한다. 기존 배포의 비밀키를 문서 또는 저장소에 붙여 넣지 않는다.
5. 배포 직후 테스트: 로그인(분대원/분대장/관리자), 7분 표시, 차력·짐승 승인, 조사 기록, 공동 방어 4종, 최종 퍼즐에 30여 명 입력, 세 엔딩과 공통 에필로그.
6. **운영 데이터가 남아 있는 상태에서 배포하지 않는 것이 좋다.** 필요하다면 관리자 백업·초기화 후 24/24 테스트를 별도의 리허설 환경에서 검증한다.
