# 거인의 기원 · 두 가지 엔딩 개편 (2026-10-20)

## 현재 서사 기준 (과거 구조 작전 이야기 대체)
**행사 이름** 너의 심장을 바쳐라 · 신조 44게오 (행사 이름의 '44'는 유지한다).
**핵심** 인류를 지키기 위해 세운 벽은 실제로 생명을 보호했지만, 언젠가는 그 안에 머무르지 않고 넘어설 용기도 필요하다. 벽 밖이 오직 죽음의 땅이라는 소문은 여섯 거인을 제압하며 찾은 증거와 모순된다.
**1차 반전** 외부에서 침공했다고 여긴 거인은 사실 **방벽 안**에서 **인류 보호**를 목적으로 제작한 방어 병기였다. 제어에 실패한 뒤 사람들을 위협하게 되었다.
**2차 반전** 벽 밖에는 여전히 위험이 있지만 강줄기, 과수원, 숲과 새 길이 표시된 **푸른 계곡**이 있다.
- 사건은 과거의 보호 시도가 실패한 비극으로 설명하며, 의도적으로 공포를 조작한 악당이나 연구 조직을 불필요하게 만들지 않는다.
- 마지막까지 비유의 해석은 참가자에게 맡긴다.
- 구 버전의 제7초소/44분대/30여 명 구조 작전과 3개 엔딩은 더 이상 현재 웹사이트 시나리오가 **아니다**. 과거 기록은 역사 자료로 보존한다.

## 운영 유지
- A–D 네 분대, 여섯 거인 부스, 정규 6R × 7분, 3R 후 8분 공동 방어, 수동 라운드 전환.
- 차력·짐승: 교관 0~10점 승인(배점 세부 운영안 미확정), 나머지: 완료 보고 시 10점.
- 공동 방어 A 단체 줄넘기 연속 5회, B 추리 퀴즈, C 젠가 수직 5개, D 티스푼으로 탁구공 전달.
- 4분대 전부 6개 미션 승인을 얻어야 최종 기록 해독 개방(24/24).
- 여섯 거인 게임은 기존 현장 활동을 사용하며, 앱에는 거인 콘셉트 기반 지시문이 표시된다.

## 라운드별 스토리 흐름
1. 여섯 거인을 쓰러뜨려 방벽을 지키라는 본부 명령.
2. 거인들을 계승할 때마다 서로 모순되는 물적 증거 확인. (팀별 방문 순서는 달라서 고정 라운드에 특정 핵심 기록이 나오는 것으로 가정하지 않는다.)
3. 3R 뒤 초대형 거인 습격, 네 분대가 방어. 전투 후 방벽 **내부의 제3공방 제어장치** 회수; 첫 번째 의문 강화.
4. 나머지 거인들의 기록을 수집해 벽 안의 제어 실패와 벽 밖 지형을 추적.
5. 전체 조사 완료 후 세 가지 구체적 정보 입력 → 진실 공개 → 계승 또는 해방 선택 → 공통 에필로그.

## 거인별 단서
| 거인 | 새 기록의 핵심 |
|---|---|
| 차력 | 신선한 벽 밖 과일과 벽 안 군수창고 봉인 |
| 짐승 | 투척 장비에 찍힌 방벽 안 제3공방 제작 번호 |
| 여성형 | 외부 무작위 습격 보고와 내부 제어 신호 기록이 서로 불일치 |
| 턱 | 주민을 보호하고 대피 시간을 확보하기 위한 방어 병기 시험 문서 |
| 갑옷 | 방벽 보강재와 같은 경질화 문양 및 제어 실패 실험일지 |
| 전퇴 | 푸른 계곡, 강줄기, 숲, 과수원과 연결된 벽 밖 지도 |

## 마지막 퍼즐 — 정확한 질문과 답
| 화면 질문 | 필수 정답 | 허용되는 표현 |
|---|---|---|
| 거인이 만들어진 곳 | 방벽 내부 | 방벽 안/벽 안/내부/방벽 안쪽 |
| 거인의 최초 제작 목적 | 인류 보호 | 주민 보호/사람 보호/방벽 방어/주민 대피 등 |
| 지도 속 벽 밖의 장소 | 푸른 계곡 | 푸른 계곡 (공백 유무 무관) |

문항 3은 '벽 밖에 존재하는 것은?' 같은 열린 질문이 아니다. 전퇴 기록에 지명이 구체적으로 등장한다.
정답은 각 분대장만 제출할 수 있다. 오류 시 재입력 가능. 해독 전에는 서버 응답에 전체 반전과 엔딩 선택지 정보가 포함되지 않는다.

## 두 엔딩
**계승 작전(inherit)** — 제어 실패의 위험을 인정하며 거인의 힘을 보급·개척에 다시 활용한다. 강력하지만 통제와 책임이 필요하다.
**해방 작전(liberate)** — 거인의 제어 장치를 봉인하고 사람들이 직접 힘을 합쳐 벽 너머로 나아간다. 더 많은 시간과 노력이 필요하다.
두 선택 모두 벽을 부정하지 않으며, 어느 쪽도 정답/오답이나 승패가 아니다.
분대장 선택은 1회만 허용되며 4분대 모두 선택하면 관리자만 공통 에필로그를 공개할 수 있다.

## 배포 전 주의: 기존 운영 상태 호환성
이번 개편으로 퍼즐 입력 필드가 `location/signal/count`에서 `origin/purpose/destination`으로 바뀌고, 엔딩 ID가 `advance/pioneer/fortress`에서 `inherit/liberate`로 바뀐다.
- **현재 진행 중인 게임 데이터를 이 버전으로 그대로 이어가지 않는다.** 구 버전의 엔딩 ID와 해독 상태가 남아 있으면 표시가 부정확할 수 있다.
- 배포 전 관리자 백업 JSON을 안전하게 보관하고, 필요하다면 리허설 데이터 초기화를 실시한다. 초기화는 참가자 진행 상황을 지우는 별도의 파괴적 작업이므로 현재 코드 변경 작업에서 수행하지 않는다.
- 데이터베이스 스키마는 변경하지 않는다. 운영 데이터베이스의 기존 설정/비밀키도 수정하지 않는다.
