# 마지막 계승자 · 벽 너머의 진실

4개 분대가 6개 구역을 순환하는 현장 야유회용 모바일 웹게임입니다. 공유 기획의 어두운 군사 작전 분위기와 기록 수집, 공동 방어, 세 가지 구조 작전 엔딩을 기준으로 재구성했습니다. 원본 HTML/ZIP의 정확한 시각 복제는 아니며, 원본 첨부파일에 접근할 수 없어 공유 대화의 설명을 기준으로 새로 구현했습니다.

배포: https://last-inheritor.vercel.app

## 운영 및 기획 문서

- [역할별 운영 가이드](docs/역할별-운영가이드.md): 일반 분대원·분대장·관리자의 메뉴, 행동, 보고·승인·종료·초기화 순서.
- [기획 및 스토리 보고서](docs/기획-보고서.md): 팀장 보고용 기획 취지, 스토리라인, 반전, 세 결말, 교훈과 운영 전제. 반전과 결말을 포함합니다.

관리자 코드·분대장 전용 링크·실제 환경변수·운영 백업은 저장소에 포함하지 않습니다. 운영자가 별도로 관리합니다. 애니메이션 이미지의 출처는 아래에 안내하며, 원 권리자의 이용·재배포 권한은 별도입니다. 이 저장소 업로드만으로 Vercel 자동 배포가 연결되지는 않습니다.

페이지별 애니메이션 장면을 추가했습니다. 입장/대기: 방벽, 현황: 조사병단, 미션: 각 거인, 기록: 지하실 열쇠, 본부: 지휘 장면, 공동 방어: 초대형 거인, 최종 선택/에필로그: 벽 너머를 바라보는 장면을 사용합니다. 이미지의 출처는 `public/image-credits.html`과 `public/scenes/credits.json`에 기록했습니다.

## 실행

Node.js 22 이상 권장. 외부 npm 런타임 의존성은 없습니다.

```sh
npm ci
npm test
npm run dev
```

로컬 주소는 http://127.0.0.1:4173 입니다. `.env.example`에 있는 이름을 기준으로 `.env.local`을 설정합니다. 인증 정보는 소스 ZIP에 포함하지 않습니다. 운영 중인 프로젝트의 환경변수는 Vercel에 저장되어 있습니다.

## 운영 순서

1. 분대원은 코드 없이 분대를 선택해 조회 전용으로 입장합니다. 분대장은 별도로 전달받은 전용 링크를 열고 입장 버튼을 누르면 해당 기기가 고정 분대장이 됩니다. 작전본부는 기존 관리자 코드로 입장합니다.
2. 본부에서 작전 개시를 누르면 1R을 시작합니다. 12분 타이머는 게임 8분과 이동 4분의 합계입니다. 라운드 이동은 수동입니다.
3. 차력·짐승은 완료 보고 후 교관이 본부 화면에서 0~10점으로 승인합니다. 나머지 구역은 분대장 보고로 10점입니다. 여성형은 추리 결과와 관계없이 완료 처리합니다.
4. 3R 뒤 초대형 거인 출현 지령을 권장합니다. 네 분대가 각각 임무를 보고하고 본부가 승인하면 성공합니다. 8분 초과 시 비상 방어로 종료합니다. 방어 시간은 정규 라운드에 보전합니다.
5. 6R과 모든 팀의 6개 미션을 마치면 최종 작전을 엽니다. 기록에서 마지막 통신을 해독하고, 세 작전 중 하나를 선택합니다. 전 분대 선택 후 공통 에필로그를 공개합니다.

부스 재료와 세부 성공 기준은 현장 진행자가 안내합니다. 현장 운영 전 각 미션의 안전선, 제한시간, 재도전 방법을 짧게 시연하세요.

## 구조와 보안

- `public/`: 로그인, 참가자, 관리자 UI. 서버 코드는 정적 배포 대상에 포함되지 않습니다.
- `api/game.js`: 관리자 코드 인증, 분대원 공개 입장, 분대장 링크 인증, 서명된 HttpOnly 세션, 동일 출처 검사, 서버 권한 검사.
- `lib/access.mjs`: 코드 없는 조회 권한과 관리자·분대장 권한을 분리합니다. 분대장 링크는 SESSION_SECRET에서 팀별로 유도한 HMAC 토큰으로 인증하며, URL의 `#` 뒤에만 포함되어 서버 접속 로그나 Referrer에 실리지 않습니다. 앱은 링크를 읽은 즉시 주소창에서 토큰을 제거합니다. 분대장 링크는 해당 분대장에게만 전달하세요. SESSION_SECRET을 변경하면 모든 분대장 링크를 다시 발급해야 합니다.
- `lib/game.mjs`: 역할별 상태 투영과 게임 전이. 아직 획득하지 않은 기록과 결말은 참가자 응답에서 제외합니다.
- `lib/db.mjs`: Supabase RPC와 버전 조건부 저장. 동시 제출이 다른 팀의 결과를 덮어쓰지 않습니다.
- `database/schema.sql`: 새 프로젝트용 스키마 템플릿. `__SECRET_HASH__`와 `__INITIAL_STATE__`는 새 설치 때 서버 비밀값의 SHA256 및 `initialState()` JSON으로 채워야 합니다. 이미 배포된 DB에는 재실행하지 마세요.
- DB는 `app_private` 스키마에 저장하며 모든 테이블은 RLS 및 직접 접근 거부 정책을 사용합니다. 공개 RPC는 별도의 서버 비밀값 없이는 동작하지 않습니다.
- 상태 동기화: 활성 탭 4초, 백그라운드 탭 15초 폴링. 푸시 기반 Supabase Realtime 구독은 아닙니다.
- 입장 제한: IP당 5분에 60회. 현장 공유 Wi-Fi의 24명 입장을 고려합니다. 동일 세션의 쓰기는 5분에 100회로 제한합니다.
- 로그인 세션은 12시간 유지됩니다. 분대장 지정을 해제하면 기존 세션의 쓰기 권한도 즉시 사라집니다.

## 배포

Vercel 프로젝트 `last-inheritor`, 팀 `ckdgus5159s-projects`에 소스 업로드로 배포했습니다. GitHub 자동 배포는 연결하지 않았습니다. 새 배포에는 `public/`, `api/`, `lib/`, `package.json`, `package-lock.json`, `vercel.json`만 업로드하세요. `.env.local`, 운영자 접속정보, 테스트 파일을 공개 파일로 올리지 마세요.

현재 설정은 `.vercel.app`의 기본 운영 URL로 접속할 수 있습니다. Vercel 보호 설정은 변경하지 않았습니다. 운영자 접속정보는 별도 로컬 파일에서 확인하세요.

## 검증과 한계

게임 전이/권한 자동 테스트와 실제 HTTP 인증·DB 조회 테스트를 포함합니다. 단일 행사 상태를 운영합니다. 본부 제어의 데이터 초기화 버튼은 확인 후 백업 JSON 다운로드를 시작하고 출정 대기로 되돌립니다. 모든 분대의 미션·점수·기록·해독·결말 및 분대장 지정이 해제됩니다. 링크와 관리자 코드는 유지되며, 분대장은 전용 링크로 다시 입장해야 합니다. 초기화는 백업한 버전과 현재 DB 버전이 같을 때만 실행됩니다. 백업 이후 진행 상태가 바뀌면 409로 중단하고 다시 백업하도록 안내합니다. 백업에는 내부 분대장 세션 식별자가 포함되므로 운영자만 보관하세요. 실제 스마트폰 24대의 동시 접속과 현장 이동통신 환경은 별도 리허설이 필요합니다.
